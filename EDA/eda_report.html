1. What Is SKILLRET?

SkillRet is a retrieval benchmark for matching natural-language user requests to AI agent skills. It contains a curated library of 17,810 public agent skills harvested from GitHub, along with synthetic training queries and human-quality evaluation queries.

The dataset consists of three core components:

  • Skills — structured metadata + full SKILL.md content for each agent skill
  • Queries — natural-language user requests that should match one or more skills
  • Qrels — binary relevance judgments linking queries to their correct skills

Additionally, the dataset includes a taxonomy with 6 major categories and 18 sub-categories that classify every skill.

2. Skill Directory Structure

Per the Agent Skills specification, a skill is a directory containing a required SKILL.md file plus optional companion folders:

  • scripts/ — executable code the agent can run
  • references/ — additional documentation loaded on demand
  • assets/ — templates, data files, static resources

The dataset only captured the SKILL.md content for each skill (body == skill_md for all 17,810 records). To determine how many skills are bare SKILL.md (nothing else in the directory) versus skills that have companion sub-folders, we analyzed the SKILL.md text for references to scripts/, references/, assets/, and other local file paths.

Key Finding: 63.5% (11,313) of skills are bare SKILL.md with no sub-folders.
The remaining 6,497 skills (36.5%) reference companion files in their SKILL.md text, indicating they were designed with a richer directory structure: 2,658 reference scripts/, 3,703 reference references/, and 677 reference assets/.

Important caveat: While these skills reference sub-folders and companion files in their SKILL.md instructions (e.g., “Run scripts/extract.py”), the actual content of those files is not included in the dataset. The dataset only provides the SKILL.md text. This means the retrieval benchmark operates exclusively on SKILL.md content, missing the richer context that ~36% of skills were designed to include.

5. Queries Component

Queries are synthetic natural-language user requests designed to match one or more skills. They were generated by two different LLMs:

  • Test split (4,392 queries) — generated by Claude Opus 4.6. These are the evaluation queries, typically longer and more complex.
  • Train split (63,259 queries) — generated by Qwen3.5-122B-A10B. These are the synthetic training queries.

Each query record includes:

  • id / original_id — unique query identifier
  • query — the full natural-language request text
  • skill_ids — list of relevant skill UUIDs
  • skill_names — human-readable names of relevant skills
  • k — number of relevant skills for this query
  • generator_model — which LLM generated the query

Golden Skills per Query

A golden skill is a distinct skill_id with a positive relevance label (relevance > 0) for that query. We count all queries in each split, including queries with zero golden skills. Duplicate positive qrel rows count only once.

Test: 2,143 of 4,392 queries (48.79%) have exactly one golden skill; 2,249 (51.21%) have multiple. Train: 42,483 of 63,259 (67.16%) have multiple golden skills.

7. Train / Test Split Design

The dataset uses a disjoint skill split: train and test skills do NOT overlap. This ensures that evaluation measures true generalization to unseen skills, not memorization.

  • Train skills: 10,123 skills with 63,259 queries and 127,190 qrels
  • Test skills: 6,006 skills with 4,392 queries and 7,187 qrels
  • Out-of-split skills: 1,681 skills in the full corpus that appear in neither train nor test splits (serve as distractors)

8. Key Findings Summary

1. Majority of skills are bare SKILL.md: 63.5% (11,313) of skills consist of only a SKILL.md file with no companion sub-folders. The remaining 36.5% (6,497) were designed with scripts/, references/, or assets/ sub-folders, but the dataset only captured the SKILL.md content — the actual sub-file contents are not included.
2. references/ is the most common sub-folder: 3,703 skills reference a references/ directory (20.8%), followed by scripts/ (2,658, 14.9%) and assets/ (677, 3.8%).
3. Software Engineering dominance: 62.2% of all skills fall under Software Engineering, with Development being the largest sub-category. AI Agents skills are the second largest group.
4. Long-tail author distribution: 2,531 unique authors contributed skills, but the distribution is heavily skewed — a few prolific authors contribute hundreds of skills while most authors contribute just one or two.
5. Query complexity differs by split: Test queries (Claude Opus 4.6) average 171 words, while train queries (Qwen3.5-122B-A10B) average 71 words. Both tend to be detailed, multi-sentence requests rather than simple keyword searches.
6. Golden skill counts differ by split: Test: 2,143 of 4,392 queries (48.79%) have exactly one golden skill; 2,249 (51.21%) have multiple. Train: 42,483 of 63,259 (67.16%) have multiple golden skills.
7. Dataset limitation — no sub-file content: The dataset provides body and skill_md fields that are byte-identical for all 17,810 records. Skills that were designed with scripts, references, or assets folders lose that context in this dataset. A retrieval model trained on SKILLRET can only match based on SKILL.md text, not the full skill package.
