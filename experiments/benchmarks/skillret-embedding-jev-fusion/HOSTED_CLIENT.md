# Hosted Jev client: preparation and safety contract

`hosted_jev_client.py` is a separate, **disabled-by-default** transport. Importing it does not read credentials or make requests. `run_jev_rerank.py execute` remains blocked; no CLI wiring was changed. Implementation and tests use only local code and synthetic fixtures. This module's existence is not evidence that the baseline passed, credit exists, a model list was fetched, or any hosted comparison ran.

The exact human approval for this experiment is a CAD $10 **all-in total**, replacing the prior limit, including smoke, pilot, any full run, conversion, fees, and buffer. No top-up or RunPod operation is implemented. The caller must preserve this approval as an auditable receipt; an arbitrary `enabled=True` switch is insufficient.


`packet` is a batch object in `preparation_manifest.json` and `request_json` is the parsed object from its `request_file`. The manifest is the existing preparation runner's exact, hash-bound object. Returned envelopes are compatible with that runner's `ingest` command and are persisted under `raw_responses/<request_sha256>.json`. Point ingestion at that directory. Successful cache reuse does not inspect the key or send another request. Partial batches never produce a partial query ranking; ingestion already enforces this.

Each `Artifact` is `(path: Path, sha256: str)`. `GateBundle` has references for `baseline_gate`, `baseline_result`, `approval`, `pricing`, `fx`, `credit`, `contract`, and `dense`. The free `model_list()` validates only the baseline, dense correspondence, and explicit budget approval; it does not read pricing/FX/credit/contract references, which can point to not-yet-created receipt files. All those receipts are required before a paid request. `model_pin` is required for paid requests. `expansion` is required beyond the ten-query smoke scope. `skills_source` is additionally required for every plan opting into `truncate_skill_md_right`, even if the particular request contains only unchanged candidates. It references the original pinned 6,006-row skills JSONL, not an exported or redacted copy. The integration must use **one experiment directory and ledger across smoke, pilot, full, and restarts**; creating a new directory would discard that directory's spending history and is not an authorized way to restart the experiment budget.

## Required receipt fields

No real hosted gate receipts have been created by this module. The following describes the schema, not assertions of verified facts.

* `baseline_gate`: the runner's actual `results/baseline_gate.json`, with `status=validated`, 4,392 queries, 6,006 skills, absolute NDCG deviation at most 0.005, and the actual encoding contract hash.
* `baseline_result`: the actual full baseline JSON, with completed status, 4,392 complete top-50 rankings, no missing evaluation queries, the exact pinned test-file hashes (including all 7,187 qrels), 32,768-token protocol, normalized embeddings, exact prefix, expected model/data/code revisions, and target-tolerance NDCG aggregates. `protocol.effective_rope_theta` must equal **1,000,000**; `document_text_sha256` and `query_text_sha256` must be present SHA256 hashes of the transformed encoder texts. The earlier partial cache using the silent Transformers 4 default of 10,000 is invalid and cannot pass this gate even if a result file claims matching metrics. The client verifies the protocol-content hash and dense ranking correspondence. The artifact hashes must be captured from the actual files, not copied from an example.
* `dense`: the actual `dense_top50.jsonl` referenced by the preparation manifest. Its bytes must hash identically and every query's ordered IDs must equal the baseline results.
* `approval`: `approved=true`, `experiment_id="newskillret-embedding-jev-fusion"`, `currency="CAD"`, `all_in=true`, `replaces_old_limit=true`, `total_cap` no greater than `"10"`, and nonempty `human_confirmation` containing the exact approval evidence.

Receipts below require `verified=true` and nonempty `source` identifying their evidence. Dated external observations also require numeric `verified_at_unix` with the freshness limits below. The promotional-cap alternative instead records the original `attested_at_unix` and does not expire as a live balance observation. In that alternative, `verified=true` describes preservation of the human attestation source, **not verification of an account balance**. Hashes ensure integrity; the external operator remains responsible for truthfully verifying receipts. Code cannot establish that a user-written `verified=true` reflects an actual source.

* `pricing` (maximum age 24 h): `currency="USD"`, `unit="per_million_tokens"`, decimal-string `input` and `output`, and stable `model`. Public pricing is recorded separately in `API_READINESS.md`; verify it again before running.
* `fx` (maximum age 48 h): `base="USD"`, `quote="CAD"`, positive decimal-string `rate`, nonnegative `fee_fraction`, `fixed_fee_cad`, and `buffer_fraction` at least `"0.10"`. Verified fees may use the existing `fees_verified=true` path. The explicit planning alternative uses `fees_verified=false`, `fee_basis="planning_allowance"`, and `source_verified=true` for the exchange-rate source; `fee_fraction` is then the nonnegative planning contingency, not a verified account fee. There is no additional contingency multiplier. Reservations use `USD * rate * (1+fee_fraction) * (1+buffer_fraction)`. A fixed fee is held once in every total-budget check. Estimated fees must remain labeled estimates.
* `credit`, verified-balance alternative (maximum age 1 h): `basis="verified_read_only_balance"` or an absent `basis` for compatibility, `currency="USD"`, positive decimal-string `available`, `read_only=true`, and `no_topup=true`. If present, `available_balance_verified` must be true. The client does not discover a credit endpoint. This path uses actual authorized account evidence; it subtracts all ledger commitments, including prior experiment usage, conservatively even when a refreshed balance already incorporates those charges. The historical `no_topup` field is an operator policy, not proof of account automatic-refill settings.
* `credit`, accepted user-attestation alternative: `basis="user_reported_promotional_credit_cap"`, nonempty `human_attestation` preserving the user's statement, numeric nonfuture `attested_at_unix` recording when it was made, `currency="USD"`, positive decimal-string `consumption_cap` no greater than `"5"`, `available_balance_verified=false`, and `no_topup=true`. Do not include `available`, `available_balance`, or `balance`: the statement supports a consumption cap and does not establish a live remaining balance. The attestation remains session evidence without a one-hour refresh; the client never rewrites its timestamp or claims a fresh observation. Before a paid call on this path, `automatic_refill_enabled` must be explicitly false. Missing, unknown or true values block before key access. This is a factual gate, not an instruction or authorization to change refill settings. A future route for enabled refills would need genuinely verified balance-minus-trigger headroom; that separate route is not implemented.
* `contract` (maximum age 30 days): `endpoint="https://api.typesafe.ai/v1/systemone"`, `models_endpoint="https://api.typesafe.ai/v1/models"`, `models_no_charge=true`, `credential_env="TYPESAFE_API_KEY"`, `rubric_sha256` equal to the preparation module's frozen five-level rubric, `total_context_tokens` no greater than 64,000, `state_plus_question_tokens` no greater than 32,000, and `token_estimator="utf8_bytes_plus_overhead_conservative_estimate"`. `max_billable_input_tokens` must be at least the total context limit and have a nonempty `reserve_allowance_basis` explaining the selected full-context reservation allowance (for example, 65,536 to allow for rounding of the documented 64k limit). **This field is a conservative spending allowance, not a claimed provider-native token bound or an independently proven maximum bill.** The provider tokenizer is not publicly documented. Byte count plus overhead is used only for deterministic packing against both context dimensions; the budget reserves the full per-call allowance rather than trusting the smaller estimate. Unexpected actual usage beyond the allowance stops all later paid calls and retains the reservation. Candidate text is never modified inside the transport. For an explicitly prepared truncation plan, this contract must additionally record `approved_oversize_policy="truncate_skill_md_right"` and `approved_truncation_policy_sha256` equal to the SHA256 of the canonical object returned by `oversize_policy_contract("truncate_skill_md_right")`. Record the already-authorized policy and its provenance accurately; these fields do not create authorization or imply provider endorsement.
* `model_pin` (maximum age 24 h): stable `actual_model` matching `jev-X.Y.Z`, `requested_alias="jev-latest"`, `alias_resolution_verified=true`, and `model_list_receipt_sha256` matching the client's saved free model-list receipt. The actual saved model-list body must contain `jev-latest`. Alias-to-version evidence must be recorded in `source`; the list can expose only aliases. Every paid response must independently return exactly the pinned actual version. The smoke requests `jev-latest` and verifies its returned version; the later benchmark requests the stable version. Identical prior smoke payloads are reused through the explicit alias-to-pin cache bridge below, without another API call.
* `expansion` (maximum age 24 h): `plan_sha256` for the exact pilot or full manifest, `based_on_actual_smoke_usage=true`, `completed_smoke_queries=10`, `projected_total_all_in_cad` no greater than the approved total, and `projected_total_runtime_seconds` no greater than 21,600. Include the actual usage/token/cost/runtime calculation and its source receipt in this artifact; do not substitute a guessed token count. A pilot and full plan need separate matching projection receipts.

Source/contract uncertainty must be recorded accurately rather than described as live verification. Tokenization uncertainty is handled through conservative packing and the full-context spending reserve, without inventing a tokenizer-proof approval requirement. The public model rate is usable for the signup account absent evidence of a custom account price; the existing stable-model price check remains. Either supported credit receipt and a correctly labeled FX/fee basis can supply the spending gates. No real receipt is created by adding these schema alternatives. The promotional route remains blocked while its factual automatic-refill state is unknown; authorized free work may continue.

## Source-bound context preparation

The default and legacy mode remains `preserve_and_block`. Existing untruncated manifests are accepted without the new source reference. The explicit alternative is the preparation module's frozen `truncate_skill_md_right` policy, version `skill-md-longest-unicode-prefix-v1`, detailed in `CONTEXT_POLICY.md`. It first tries every complete candidate independently, then removes only the right suffix of `skill_md` when the conservative estimate requires it. It retains the longest fitting Unicode-codepoint prefix; task, name, description, question prefix, rubric, candidate IDs and dense ranks remain unchanged. Batches follow the original dense order. No candidate or selected query is silently omitted.

Before even reading `TYPESAFE_API_KEY`, the client matches the manifest's `context.oversize_policy`, exact `truncation_policy` object and `truncation_policy_sha256` against the frozen implementation and the recorded contract approval. It checks the two supplied context limits against the provider contract, recomputes aggregate query/batch/pair/truncation counts, and checks the estimator version. It reads and hashes `skills_source`, requires the official pinned SHA256 and 6,006 unique IDs, then calls `build_batches` again on the original twenty skill records and the manifest's unchanged query/model/context settings. Every audit field, every deterministic batch packet and the actual request must exactly match this reconstruction. Rehashing an altered audit, substituting different text, shortening a prefix further, changing metadata or the rubric, or inventing a token count cannot pass this check. Failures occur before key access, a spend reservation, or a transport call.

The original catalogue is cached by path, pin, size, modification time and creation/change time; any changed identity forces a fresh hash and parse. Recomputed rows are cached only under that source identity, the exact manifest hash, query ID and requested model. The client does not write original catalogue text to diagnostic output. This binds skill text to the actual source bytes; the query source still uses the existing manifest hash/ID and request-state checks rather than a second source-file replay.

Requests also undergo a local credential-shaped-text check before credential access. A suspected GitHub token or private-key header blocks that batch for private audit; the error contains only the request field path and a SHA256 of the matched text. Explicit all-x GitHub-token documentation placeholders are allowed. This is a narrow precaution, not a comprehensive secret detector or a claim that a matching public example is a real secret. It neither rewrites nor redacts request text and makes no automatic retry or bypass. Original data remains local for review.

## Budget, persistence, and failures

Before each HTTP POST, the client acquires `budget_ledger.lock`, checks committed CAD against approval and committed USD against the applicable `usd_cap`, and fsyncs a reservation for the full input-token allowance to `budget_ledger.jsonl`. The internal name `usd_cap` covers both receipt alternatives without relabeling a user-reported consumption cap as available balance. Reservations record the cap, receipt basis and receipt hash. A previously reserved promotional cap remains a ceiling across client restarts or replacement receipts; all prior actual charges and unresolved reservations count against it. The smaller packing estimate is recorded separately. The lock covers the whole request and settlement. Ledger events have sequence numbers, experiment identity, previous-event hashes, and event hashes. Partial trailing writes or hash mismatches fail closed. It uses exclusive creation for locking and append plus flush/fsync for the journal. This is durable single-writer protection, not a transactional remote billing system. These local caps do **not** independently prevent account-level automatic-refill purchases or charges made outside this experiment.

The sole credential expression is `os.environ["TYPESAFE_API_KEY"]`, reached only after gates and budget validation. There is no saved-secret fallback, SDK credential discovery, `.env` loader, key-printing path, or credential in artifacts. The standard-library transport has no automatic retries, proxy-environment discovery, or redirects. URLs are fixed allowlisted TypeSafe endpoints. It captures only the safe `x-typesafe-request-id` header; Authorization and other headers are never persisted.

Exact canonical request bytes are preserved under `requests/<request_hash>.json`. For every response, exact HTTP body bytes are written and fsynced to `attempts/<request_hash>-<attempt>.body` **before** UTF-8 decoding or JSON parsing. A companion `.json` records status, request/response hashes, latency, request ID, plan identity, and attempt ID. HTTP 200 responses need a pinned actual model, valid scores, and input usage within the held allowance before settlement. Unknown input usage, a changed version, malformed JSON, or a non-200 outcome retains the reservation and blocks **all further paid requests in the experiment**, including different query hashes. Output usage may remain null only when the verified output price is zero; it is recorded as unknown, never fabricated as zero tokens.

To avoid paying again when smoke's `jev-latest` becomes the stable model ID, `semantic_cache` hashes a comparison payload with **only** `model` normalized to the verified actual model. All remaining fields must compare exactly, as must the candidate/question ID mapping. Reuse requires the original immutable request bytes, original raw response bytes, pinned actual response model, and a settled original ledger event. It never combines different batches. The target ingestion envelope sets `request_sha256` and `expected_request_sha256` to the target manifest request; `original_transport_request_sha256` identifies the request that was actually sent. The `cache_reuse` object explicitly records alias-to-pin equivalence and zero additional calls/tokens/cost. Original raw response, usage, latency, and hashes remain unchanged. The original transport payload is never relabeled as a stable-model request. A ledger `cache_reused` event has no reservation or spend.

For total experiment billing, sum the ledger's actual settlements (and account for unresolved reserves). Do not add usage totals from overlapping smoke/pilot/full ingestion reports: their reused envelopes preserve the original call's usage as evidence and therefore describe overlapping logical scopes. Additional billed usage on the bridge is explicitly zero. Question-to-candidate mapping, full-text audit hashes/counts, and complete top20 batch partitioning are validated before key access so rehashed malformed manifests cannot silently assign responses to the wrong skills.

Timeouts, disconnects, process interruption, and default HTTP 429/529/5xx handling are ambiguous. They are never blindly retried. Every unresolved reservation blocks paid continuation. A crash before settlement may have paid successfully, so missing cache data is not permission to repeat the call. Manual reconciliation must use provider request IDs and billing/usage evidence. This module intentionally supplies no automatic unlock, reset-budget, discard-reservation, or ambiguous-retry command. Key availability is checked after every evidence and budget gate, but before reserving: a missing key sends no HTTP request, creates no reservation, and is reported explicitly so free work can continue.

`documented_no_execution_statuses` defaults to `{}` and `max_attempts` to `1`. Future verified provider documentation that explicitly guarantees both no execution and no billing can be represented as a mapping from status string to exact evidence URL; only these statuses release their reservations and permit bounded retries. `max_attempts` cannot exceed three and backoff is bounded. **Current public TypeSafe docs recommend retry/backoff but provide no such guarantee; the real receipt must therefore keep this mapping empty.** The synthetic retry test does not establish a provider guarantee.

## Offline validation and limitations

Run `python -m unittest test_hosted_jev_client -v`. Tests mock the environment and transport, create only temporary synthetic evidence, assert no credential read on absent/failed gates, check immutable raw evidence and cached resume, enforce the total budget, and exercise timeout/unknown-usage/global blocking and safe-retry bookkeeping. Additional cases accept a valid source-backed Unicode truncation fixture and reject absent source/policy, a changed source, rehashed text or audit changes, wrong counts/context settings and a legacy-policy downgrade before any key access. Credential-shaped synthetic test strings are generated locally; failures expose only hashes and safe field paths. They do not prove service availability, provider billing semantics, context-token parity, or result quality. Public evidence remains in `API_READINESS.md`.

Receipt-alternative tests additionally cover an accepted synthetic promotional cap with planning fees, missing/unknown/enabled refill states, fake balance claims, invalid caps, missing FX-source verification, persistent prior spending and caps across restarts, historical verified-balance compatibility, and retention of the original attestation timestamp without a live-balance expiry. The baseline artifacts are cached in memory per unchanged path/hash/size/mtime identity for efficient repeated requests. These checks address accidental changes; the workspace is not an adversarial integrity boundary. Stable artifact hashes, truthful external receipts, and one experiment ledger are part of the operator contract. No live endpoint or real credential was used to build or test this module.
