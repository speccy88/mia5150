# Runtime compatibility findings

1. The installed Transformers 4.57.1 SDPA adapter selects native grouped-query attention when PyTorch >=2.5. On SM75, memory-efficient attention requires equal query/key/value head counts; Flash and cuDNN alternatives are unsupported or disabled. The first guarded feasibility run failed with `No available kernel`, without a completed vector. The runner selects the adapter's own equivalent `repeat_kv` branch and leaves the memory-intensive math fallback disabled.

2. The saved Transformers 5.5.4 model configuration contains nested `rope_parameters = {"rope_theta": 1000000, "rope_type": "default"}`. Transformers 4.57.1 preserves that dictionary but sets the independent effective `rope_theta` attribute to 10000. A direct AutoConfig inspection confirmed this mismatch. The initially successful hardware fit run and interrupted full run therefore used incorrect rotary frequencies. Their cache contract `04df631ea318ebe961ea0e9a3e547e7407e062250019138d671f9852f270506c` is invalid for benchmark results and must never be reused as the baseline. The stopped partial cache is preserved, not deleted or relabeled.

The corrected loader reads the pinned configuration, explicitly translates the nested value into the older runtime's `rope_theta`, disables nonexistent scaling, and verifies the actual frequency buffer against the expected 1,000,000-base formula. The encoder-source hash changes the cache identity, preventing cross-contamination. Hardware fit alone does not establish semantic reproduction. Only the final full-query target comparison can validate the baseline.

3. Run `06-full-correct-rope` stopped after 5,566 journaled document vectors on the requested sustained host CPU guard: five consecutive samples exceeded 80%. Its valid completed vectors were retained. A 0.05-second pause after each new forward was added without changing model inference or embedding identity. No memory, VRAM, temperature, CPU or swap threshold was relaxed. After exit, fresh host telemetry showed 5% CPU and roughly 7.24 GiB available memory.

4. Run `07-full-cpu-cooldown` left 6,006 valid document vectors and 961 query vectors, then ended without an exit or guard-stop receipt. Its last saved telemetry was UTC epoch 1791333652.5191433, with 56% host CPU, unchanged zero swap counters, and 1,303 MiB GPU use. Subsequent inspection found no worker. The cause of this interruption is unknown; it is not claimed as a completed run or a guard success. Run `08-resume-query-cache` resumes the hash-verified cache under the same guards and cooldown.

Active query encoding/search latency excludes the inter-forward safety pause, cache flush and startup. Telemetry timestamps include those delays and interruptions. Active operation latency must not be mistaken for end-to-end throughput. Cache progress, hardware fit and a resumed process are not reproduction evidence; the complete rankings and official metric comparison decide the final gate.
