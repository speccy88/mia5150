# Implementation corrections retained with the campaign

The frozen scientific factors and query panel remain unchanged. Before resumed selection, inspection of the first resource-stopped invocation found that the runner treated `not_run_resource_guard` rows as finished cases. That contradicted the protocol's resume rule. The correction resumes only cases that received no attempt, appends a new row, and retains the old unattempted row. Attempted successes and failures are never retried. Aggregation selects the latest record only where every prior record was explicitly unattempted, and checks that invariant. Runtime caps accumulate across invocations.

The first invocation contains12 valid cases,1 pipeline failure and5067 unattempted cases. Its failure remains in the planned denominator. Fully sequential preparation/selection replaces concurrent CPU preparation after the memory guard fired. ONNX CPU memory arena/pattern caching are disabled to reduce retained RAM. This changes allocation behavior, not tokenizer, weights, text, pooling, ranking rules or inference parameters. All failed setup attempts and resource receipts remain evidence; their incomplete vectors are not quality results.
